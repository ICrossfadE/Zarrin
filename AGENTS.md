# Інструкції для агента — Zarrin

## Перед початком роботи

1. Перечитай усі доступні файли проєкту: код, конфігурації, README, docs та task, включно з вкладеними інструкціями. Спочатку склади перелік через `rg --files --hidden`. Не читай вміст секретів, `.git`, `node_modules`, `.next`, кешів і згенерованих файлів. Для бінарних ресурсів перевір призначення та метадані, зображення переглядай за потреби. Якщо обсяг перевищує контекст, читай частинами, не пропускаючи авторські файли мовчки.
2. Перевір поточні зміни; не перезаписуй чужу роботу.
3. **Перед будь-якими змінами** створи `task/NNN-short-name.md`: мета, обсяг, що не входить, покроковий план, критерії прийняття та перевірки. Створення самого запису задачі — перша дозволена зміна. Продовжуючи ту саму задачу, онови її замість дублювання.
4. Якщо Next.js містить локальну документацію в `node_modules/next/dist/docs`, читай відповідні розділи перед змінами API; інакше використовуй офіційну документацію встановленої версії.

## Межі повноважень

- Поточний етап: лише локальний каркас та документація. Нові сторінки й анімації починай після відповідного запиту власника.
- Без згоди власника не підключай CMS, хостинг, DNS, аналітику, моніторинг, пошту, зовнішні API, вебхуки й інші сервіси. Не публікуй проєкт і не створюй сторонні акаунти.
- Встановлення локальних пакетів для погодженого стеку не означає дозвіл на підключення сервісів.
- Форми — тільки інтерфейс: жодних відправлень, збереження, API, Server Actions, інтеграцій або імітації успішної відправки. Кнопки макетних форм — `type="button"`; не допускай submit або передачі введеного в URL.

## Правила реалізації наступних етапів

- Next.js App Router, TypeScript strict, Tailwind CSS. Компоненти серверні за замовчуванням; `use client` тільки для необхідної інтерактивності й GSAP.
- Figma та style guide — джерело істини. Посилання: `docs/figma.md`. Не називай неперевірені значення токенами макета. Зберігай погоджені ресурси локально.
- Для погодженої реалізації Figma в коді використовуй `$figma-mcp-to-code`; вихідні інструкції навички: `skills/figma-mcp-to-code/SKILL.md`. Починай з перевірки MCP-конектора, а не зі звичайного вебвідкриття Figma. Саме створення навички не запускає верстку.
- Всі сторінки адаптивні; перевіряй desktop і mobile. Contact і 404 не мають окремих наданих mobile-посилань — продумай адаптацію за загальною системою дизайну, зафіксуй припущення.
- Усі секції мають GSAP reveal; враховуй `prefers-reduced-motion`, cleanup і доступність контенту без JavaScript. Не приховуй серверний контент назавжди до запуску анімації.
- Інтерактивні елементи: `cursor-pointer`, hover, transition, `focus-visible`; disabled має відповідну семантику. Не роби статичний контент клікабельним на вигляд.
- Семантична HTML-структура, доступні labels, alt та клавіатурна навігація. Використовуй `next/link` і `next/image`, де доречно.
- Спочатку локальні типізовані дані блогу. CMS-провайдер обирається окремо; деталі провайдера не мають потрапляти в UI.

## Коментарі та завершення

- Залишай українські коментарі для власника біля нетривіальних рішень, тимчасових обмежень і припущень. Не коментуй очевидний синтаксис.
- У задачі записуй зроблене, команди перевірок, результати, відкриті питання та наступний крок.
- Для коду виконуй `npm run lint`, `npm run typecheck`, `npm run build`. Для UI додатково перевіряй браузер, адаптивність, hover/focus і reduced motion. Не вигадуй успішні перевірки.
- Оновлюй docs відповідно до фактичної реалізації. Відрізняй заплановане від виконаного.
