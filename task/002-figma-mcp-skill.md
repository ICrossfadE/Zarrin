# 002 — Навичка Figma MCP → код

Статус: виконано.

## Мета й обсяг

Створити повторно використовувану навичку `figma-mcp-to-code` для читання дизайну через доступний MCP-конектор Figma та реалізації у поточному стеку проєкту. Зберегти вихідні файли в `skills/figma-mcp-to-code`, перевірити та встановити в персональну папку навичок Codex.

Не входить: верстка сторінок, встановлення MCP-сервера/плагіна, авторизація Figma, зміни застосунку або підключення сервісів.

- [x] Врахувати адаптивність, локальні правила, GSAP та інертні форми Zarrin.
- [x] Перевірити структуру навички й сценарії відсутнього/неповного MCP-контексту.
- [x] Встановити перевірені файли у персональну папку навичок та звірити копії.

## Критерії прийняття

Навичка придатна до виклику як `$figma-mcp-to-code`, спочатку перевіряє доступні MCP-інструменти, не підміняє їх вебскрейпінгом, не вигадує доступ до Figma або токени, не змінює Figma та не підключає сервіси. Вона описує перевірку реалізації у браузері й чесне звітування про обмеження.

## Коментар для власника

Навичка — це workflow агента, а не MCP-сервер: сама по собі вона не надає доступ до Figma. Для виконання потрібний доступний і авторизований конектор. Поточна задача створює навичку, але не починає верстку.

## Результат і перевірки

- Створено `skills/figma-mcp-to-code/SKILL.md` та `agents/openai.yaml`. У AGENTS.md додано правило застосування для майбутньої реалізації.
- Встановлено в `C:/Users/Cross/.codex/skills/figma-mcp-to-code`; обидва файли звірено за SHA256, копії ідентичні.
- YAML frontmatter, назва, допустимі поля, довжина description, відсутність scaffold placeholders та UI metadata перевірені через Node.js з наявним js-yaml. Автоматичний вибір увімкнено; default_prompt містить `$figma-mcp-to-code`.
- Bundled `quick_validate.py` запущено, але його виконання блокує відсутній Python-пакет PyYAML. Замість додавання залежності виконано відповідні структурні перевірки через js-yaml; штатний Python-валідатор не пройдено.
- Вручну переглянуто workflow для відсутніх MCP-інструментів, auth/file/node errors, sparse context, відсутнього mobile frame та виконання поза Zarrin. Реальний MCP → код прогін не виконувався: запит стосувався створення навички.
- Код і залежності застосунку не змінені; lint/build не повторювалися, оскільки змінені лише Markdown та metadata навички.

## Межі та наступний крок

MCP-сервер або плагін не встановлено, авторизацію не налаштовано, Figma не змінено. Для наступного запиту реалізації викликати `$figma-mcp-to-code` із цільовим посиланням; тоді навичка почне з discovery фактично доступного MCP-конектора.
