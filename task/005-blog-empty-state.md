# 005 — Порожній блог і недоступний API

Мета: сайт рендериться, навіть якщо getPosts() завершується помилкою або повертає порожній список; замість статей показано зрозумілий empty state.

Обсяг: обробка помилок читання статей, спільний порожній блок для секцій Home та списку Blog, порожній пошук, документація та перевірки. Не входить: налаштування/запуск CMS, зміна секретів, нові сервіси, редизайн сторінок, логіка форм.

План:
1. Прочитати авторські файли та поточні зміни, зберегти попередню роботу task/004.
2. На межі getPosts() перехопити помилки запиту/парсингу, повернути [] без демо-даних і часткового результату пагінації; залишити серверну діагностику.
3. Додати спільний адаптивний блок «No posts yet» лише замість карток Home та списку Blog; зберегти Home з hero, решту сторінок і пошук без даних.
4. Виконати регресійні перевірки, lint/typecheck/build, HTTP і браузерний перегляд desktop/mobile, focus/hover та reduced motion.
5. Оновити документацію й записати фактичні результати.

Критерії: Home/Blog/About/Contact не повертають 500 через збій API; Home з hero та секціями збережена, лише картки Home та список Blog показують empty state, якщо список порожній/недоступний. Відсутній у списку slug лишається 404. Успішні відповіді зберігають поточний UI; наступний запит може відновити дані. Header/Footer/навігація залишаються доступними. Немає секретів у UI, моків у застосунку або нових залежностей.

Початковий Git: зміни task/004 у README/docs, сторінках, Header, blog.tsx, repository/types; видалений mock-posts.ts, невідстежувані blog-posts.ts, src/lib/ та task/004. Не скидати й не перезаписувати.

Припущення: однаковий нейтральний empty state для порожньої CMS і тимчасової помилки погоджено запитом власника. Це інженерне доповнення до поточного UI, окремого Figma-макета немає.

Уточнення власника: повністю зберегти Home, включно з hero й усіма секціями. Empty state показувати лише замість карток у секціях Home та у списку Blog. CTA hero без featured веде на /blog. Поведінка шаблону статті/404 залишається попередньою; не замінювати сторінки порожньою заглушкою.

## Результат

Виконано: getPosts() перехоплює помилки завантаження/JSON/нормалізації і повертає [] із нейтральним серверним попередженням без секретів. Часткові сторінки пагінації не показуються. На наступному рендері CMS читається повторно; успішні дані не замінюються моками.

PostsEmptyState показується у трьох блогових секціях Home і замість списку Blog. Home завжди зберігає hero, фото, CTA та заголовки секцій; CTA без featured веде на /blog. Початкове раннє повернення цілої заглушки прибране після уточнення власника. Header/Footer, About, Contact і шаблон статті/404 збережені. Пошук із [] одразу показує «No posts available right now». README/architecture/plan оновлені.

Перевірки:
- `node task/check-blog-fallback.mjs` — успішно: connection refused, timeout, HTTP 403/500, invalid JSON/envelope/null, unsupported content, порожня успішна відповідь, відмова другої сторінки, відновлення наступного запиту, lookup/groups. Виконується справжній API helper/getPosts/repository через TypeScript transpileModule/vm; fetch контрольований лише у перевірці. React cache у цьому скрипті не перевіряється.
- `npm run lint` — успішно після виправлення локальної назви testModule у перевірці.
- `npm run typecheck` — успішно.
- `NEXT_TELEMETRY_DISABLED=1 npm run build` — успішно поза sandbox після остаточного відновлення Home; всі шість типів маршрутів dynamic. Початкова sandbox-спроба завершилася webpack errors без деталей.
- `node task/check-blog-pages.mjs` — успішно на dev-сервері з недоступною CMS: HTTP 200 для /, /blog, /about, /contact; HTTP 404 для /missing-page. Home містить hero і всі секції, рівно три empty-блоки, Blog — один. Header/Footer і SSR-контент присутні, form та inline opacity:0 немає.
- Браузер desktop (~1280 px) і mobile (390 px): hero та секції Home присутні; empty-блоки відображаються замість карток, Blog зберігає вступ. Горизонтального overflow немає; при viewport 390 canvas 375 через scrollbar. Тимчасовий viewport скинуто.
- Пошук на localhost:3000 відкривається з порожнім повідомленням; Escape закриває й повертає focus на Search articles, outline 3px. Журнал спостереженої вкладки без error/warn перед перезапуском. Для 127.0.0.1 Next.js попереджав про blocked dev HMR origin; фінальна інтерактивна перевірка виконана на localhost без зміни конфігурації.
- Hover/transition і reduced motion перевірені статично в наявних CSS/Reveal: умовний GSAP no-preference, cleanup, видимий SSR. Окрема runtime-емуляція reduced motion та hover не виконана.
- `git diff --check` — успішно, тільки попередження LF/CRLF. Попередні зміни task/004 збережено.

Залишено `npm run dev` на http://localhost:3000; вкладка показує відновлену Home. Наступний крок: перегляд власником; реальні картки повернуться після відновлення CMS і оновлення сторінки. Live-перевірка непорожньої CMS у цій задачі не виконувалася; успішне завантаження перевірено ізольованим регресійним сценарієм. Максимальне очікування несправного API лишається наявним timeout 10 секунд.
