## Актуальний стан — 2026-11-17

Локальний frontend етапів 1–5 реалізовано через погоджене читання настільної Figma: шість типів сторінок, 10 локальних slug, спільні компоненти, responsive CSS, GSAP, пошук і меню. Contact mobile та 404 mobile знайдено у файлі; припущення щодо відсутніх фреймів більше не потрібні. Деталі, межі візуальної звірки й результати перевірок — [design-audit.md](design-audit.md) та [task/003](../task/003-figma-pages.md).

Наведений нижче план описує початковий порядок робіт. CMS, фінальні контакти/контент/соціальні URL, юридичні питання, домен і публікація залишаються наступними окремо погоджуваними етапами. Жоден зовнішній сервіс не підключений.

## 0. Ініціалізація — поточна задача

- [x] Базовий Next.js App Router, TypeScript strict, Tailwind CSS, ESLint.
- [x] Архітектура, план, Figma-посилання, AGENTS.md та task/001.
- [x] Встановити залежності й завершити lint, typecheck, production build та HTTP smoke-перевірки; підсумок у task/001.

Цей етап не включає верстку Figma, CMS або публікацію.

## 1. Аудит дизайну

- Отримати доступ до Figma, переглянути всі desktop/mobile frames та style guide.
- Записати підтверджені токени, шрифти/ліцензії, grid, assets, повторювані секції та стани.
- Визначити адаптацію Contact і 404, для яких окремі mobile frames не надані.
- Перевірити призначення видимих кнопок, пошуку, соціальних посилань і пагінації. Не вигадувати URL чи поведінку.

Критерій: список секцій і перевірені параметри дизайну, придатні для верстки.

## 2. Основа інтерфейсу

- Локальні assets, Tailwind tokens, typography, Container, Button, поля.
- Header/Footer, mobile menu, активна навігація, focus/hover/transitions.

Критерій: повторювані елементи відповідають Figma, працюють на клавіатурі та mobile.

## 3. Локальні шаблони блогу — першочергова верстка

- Post model, локальні fixtures, repository без CMS.
- `/blog`: список статей і повторно використовувані картки.
- `/blog/[slug]`: єдиний шаблон статті, локальний контент, пов'язані публікації за макетом.
- Коректна 404 для невідомої статті.

Критерій: щонайменше дві локальні статті через один шаблон; desktop/mobile відповідають макетам. Це демонстраційні дані, а не підключена CMS.

## 4. Решта сторінок

- `/`: Home з повторним використанням карток і даних.
- `/about`: About.
- `/contact`: Contact з інертною формою.
- `not-found.tsx`: оформлена 404.
- Всі форми, включно з підпискою, не надсилають і не зберігають нічого.

Критерій: шість типів сторінок, робочі внутрішні переходи, адаптивність без overflow.

## 5. GSAP та перевірка інтерфейсу

- Додати GSAP reveal до всіх секцій, врахувати reduced motion та cleanup.
- Перевірити повторну навігацію, контент без JS, hover/focus і мобільне меню.
- Візуально порівняти всі сторінки з Figma на desktop/mobile, перевірити проміжні ширини.
- Виконати lint, typecheck, build; перевірити відсутність submit-запитів та hydration errors.

Критерій: повна frontend-версія на локальних даних без зовнішніх сервісів.

## 6. CMS — тільки після вибору й згоди

- Визначити редакторські ролі, мову контенту, draft/preview, категорії, медіа й бюджет.
- Обрати CMS, розробити схему, замінити repository, погодити хостинг/БД за потреби.
- Налаштувати доступи, перевірку контенту, оновлення кешу та резервні копії.

Критерій: редактор може публікувати/оновлювати статті; вони з'являються на сайті. Жодна форма сайту не отримує серверну логіку через підключення CMS.

## 7. Публікація — окреме погодження

- Погодити хостинг, домен/DNS, CMS та необов'язковий моніторинг.
- Налаштувати релізні перевірки, HTTPS, секрети, резервне копіювання та відновлення.
- Завершити SEO, метадані, sitemap/robots, перевірити продакшн і сторінку 404.

Критерій: сайт доступний на погодженому домені, контент відновлюється з резервної копії, відсутні небажані інтеграції.

## Рішення, які ще потрібні

Ці питання не блокують початкову підготовку: доступ до style guide, мова фінального контенту (тимчасово `en` за англомовним шаблоном), справжні статті/контакти/соціальні URL, права на фото й шрифти, CMS та бюджет, домен і хостинг. Форми залишаються інертними, доки власник явно не змінить вимогу.
